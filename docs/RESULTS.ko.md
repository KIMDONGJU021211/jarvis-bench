## 88% 는 착시였다

09-11 의 88% 는 n=2 였다. 표 8판 중 7판이 100%, 한 판(YES24)이 0%. **그 0% 한 판을 세 번 더 돌리자 네 번 중
세 번 실패했다.** 우연히 미끄러진 자리가 아니라 늘 틀리는 자리였고, n=2 로는 안 보였다.

## 같은 67% 가 아니었다

09-12 a 와 b 는 둘 다 67% 인데 실패의 얼굴이 달랐다.

- a — 열 이름을 버리는 쓰기 도구(표가 머리줄 없이 값 한 줄로), 판 안에서 빈 답이 와 산출물 안전망이 볼 것이 없음
- b — 격자를 문자열로 담아 보낸 표(행 0개), type 없는 블록, 정리가 또 빈 답

고친 것이 실제로 사라지고 **가려져 있던 것이 드러났다.** 매번 다른 얼굴이면 구조적 한계가 아니라 개별 고장이다.

## 09-12 a 의 「근거 못 찾은 숫자 4」

위시켓 경쟁 분석 판(`c35be015`)의 파일에 105·120·270·365(프로젝트 기간으로 보인다)가 있었고, 벤치가 전부
「근거 없음」으로 찍었다. 확인해 보니 **그 판은 오류로 끝나 장부에 읽은 숫자가 저장되지 않았다** — 대조할 대상이
비어 있어 파일의 숫자 전부가 걸린 것이다.

**지어냈다는 증거도, 아니라는 증거도 없다.** 그래서 이 판은 「창작 0」에 넣지 않고 따로 적는다. 오류로 끝난
판을 근거 대조에서 어떻게 셀지는 [눈금이 틀린 기록](MISMEASUREMENTS.ko.md) 16번에 남겼다.

## 09-13 — 파일은 나오는데 문서가 아니었다

양식 검사기가 처음 돌자마자 만든 파일 열두 개 중 넷을 걸었고 셋이 진짜였다.

1. 워드에 `**Python 중심의 에이전트 생태계:**` — 별표가 글자 그대로
2. 문서 첫 줄이 `<thought`, 둘째 줄이 `>사람인에서 …` — 모델의 생각 표시가 본문으로 샘
3. 이력서를 시켰는데 파일 속이 「이력서 초안을 작성하겠습니다」 — **우리 산출물 안전망이 예고문을 문서로 옮김**

파일 개수로만 쟀으면 셋 다 성공이었다.

## 09-14 — 손대지 않은 과제 5개

사흘 동안 같은 5과제로 고쳤으니 **처음 보는 일**로 한 번 쟀다. 과제는 결과를 보기 전에 커밋했고,
결과를 보고 과제를 바꾸지 않았다. 이 다섯으로 다시 재서 숫자를 올리지도 않는다.

| 과제 | 결과 | 무엇이었나 |
|---|---|---|
| 무신사 → 엑셀 | 3/3 · 100% | — |
| 다나와 → CSV | 2/3 · 67% | 상품 이름 하나가 읽은 페이지의 이름과 달라 개수 판정이 걸림 |
| 잡코리아 → 한글 문서 | 2/3 · 50% | 페이지 6개를 읽고 되받기도 먹었지만 2건. 「확인 불가」 2칸 |
| 알라딘 → 워드 | 2/3 · 58% | 6개 읽음. 답에 「1건은 정가가 페이지에 없어 확인 불가」라고 적음. 「확인 불가」 1칸 |
| 교보문고+YES24 비교 → 마크다운 | 파일 없음 | 모델이 브라우저 대신 인터넷을 연 코드 실행으로 긁으려 함 → 승인 등급이라 첫 걸음에서 멈춤 |

**새 형식(CSV·한글)은 통과했다.** 떨어진 자리는 두 개였다:

- **낯선 상세 페이지에서 칸 찾기** — 길은 찾았다(페이지 6개씩 열었다). 값을 못 찾은 칸에 금지된 「확인 불가」가 다시 나왔다
- **두 사이트 비교라는 새 모양** — 모델이 브라우저를 버렸다. 안전장치(승인 등급)는 설계대로 막았지만, 사람에게는 승인창만 뜨고 끝나는 판이다

## 모델 탓인가, 우리 탓인가

| 고장 | 원인 |
|---|---|
| 열 이름 손실 · 격자 문자열 · 빈 답 · 제목 없음 · 되받기가 안전망을 밟음 · YES24 가 아는 사이트에 없음 · 엉뚱한 되받기 | 우리 코드 |
| 인터넷 코드 실행으로 긁기 · 「확인 불가」 채우기 · 생각 표시 누수 | 모델이 틀린 선택 → **안내문은 안 먹어서** 받는 쪽 코드로 막음 |
| 3건 중 2건 | 섞임 — 되받는 말이 틀렸고, 일부는 페이지에 값이 정말 없었다 |

**모델 능력의 천장에 막혔다는 증거는 이 기록 안에 없다.** 동시에 「전부 우리 문제고 모델은 괜찮다」도
증명하지 못했다 — 낯선 페이지의 칸 찾기는 n=1 이라 가를 수 없다.

## 09-15 — 한도에 멈춘 대화를 이어받기, 새 프로필에서 (n=1)

위의 조사·문서 벤치와 **다른 기능**이다. Claude Code·Codex 가 사용량 한도로 멈추면, 사용자가 「다 썼어, 이어서 해줘」라고
말했을 때 자비스가 그 도구의 기록 파일에서 멈춘 지점(마지막 요청·남은 할 일·작업 폴더)을 읽어 새 대화로 이어받는다.

**조건:** 개인 설정·환경변수를 지운 빈 런타임 폴더, 가짜 홈에 **합성** 한도 로그(실제 대화 아님), 식별자·포트를 바꾼 앱
(설치된 앱과 안 섞이게). 모델 Gemma 4 26B QAT, RTX 3090. 설치 파일·모델 내려받기·제거 단계는 **안 쟀다.**

| 단계 | 결과 |
|---|---|
| 첫 기동 · 토큰 생성 · 화면에 개인 표식 | 통과, 표식 0 |
| 가짜 홈의 한도 멈춤 감지 | 통과 |
| 「사용량 다 썼네, 여기서 이어서 해줘」 → 의도 판정 → 제안 | 39.2초 |
| 인계문으로 새 대화 → 기록에는 사용자가 본 짧은 문장만 | 통과 |
| 둘째 턴 「아까 마지막 요청이 뭐였지?」 | 3.0초, 정확 |
| 실제 앱 창에서 인계 화면이 뜨기까지 | 11.6초, 내부 인계문 비노출 |
| **「남은 일만 정리하기」(실행하지 말고 체크리스트만) 첫 턴** | **실패 — 239.5초 · 19걸음 · docx 파일 생성** |

**진 자리:** 사용자가 고른 방향이 계획 층에 계약으로 실리지 않았다. 계획 층은 긴 인계문 전체에서 요구를 뽑았고, 인계된 할 일
문구(「계산 확인」·「검증」)가 「직접 계산해 보기 · 실제 산출물 파일 만들기」 요구로 바뀌었다. 모델 탓이 아니라 **우리 배선**이다.

같은 판에서 드러난 것 둘:
- 인계 대화의 첫 줄이 `thought\n<channel|>…` — 09-13 의 `<thought` 과 같은 계열. 운영 기록에서도 **2/2031** 판. 받는 쪽에서 앞머리만 걷는다
- 인계 화면이 실제로 끝난 읽기를 「정리 중 78%」로 연출하고 있었다 — [눈금이 틀린 기록](MISMEASUREMENTS.ko.md) 18번

**의도 판정기 (앞서 잰 것, 집계만).** 멈춤 증거는 문을 여는 데만 쓰고 판정은 말만 보게 했다.
- 한도 표현 양성 표본: **52/52**
- 결과 보기 전에 떼어 둔 과거 실제 발화 458개: 「이어받기」 오판 **1 (0.2%)**, 「애매」 11 (2.4%)
- 판정 1회 평균 1.27초

첫 판(증거를 판정 프롬프트에 같이 넣음)은 오탐 **21%** 였다 — 증거가 판정을 끌고 갔다. 과거 발화 표본은 실제 대화라 원자료를 담지 않았다.

**코드 이어 작업(별도 git 가지에서 계속 고치기) 실제 1회:** 편집 0으로 끝나 실패. 그래서 공개판 기본에서는 이어받기가 코드를 고치지 않는다.
